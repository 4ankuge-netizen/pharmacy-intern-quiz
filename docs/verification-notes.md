# PMDA確認作業のメモ

このファイルは、旧プロジェクトから取り込んだ1,555問を、PMDAの添付文書と
照らし合わせて確認していく作業の記録です。

作業の手順と、確認できなかった問題の理由を残しています。
続きから作業するとき、また同じ壁にぶつからないための覚書です。

## 作業の手順

```bash
# 1. まだ添付文書を取っていない薬の一覧を作る(出題数の多い順)
node tools/list-drugs-to-fetch.mjs --difficulty beginner --limit 100 > /tmp/drugs.txt

# 2. PMDAから添付文書を取ってくる(.pmda-cache/ に保存される)
node tools/fetch-pmda-documents.mjs --from-file /tmp/drugs.txt

# 3. 取ってきた文書が本当にその薬のものか点検する
node tools/audit-pmda-cache.mjs

# 4. 問題と、根拠になるはずの記載を並べて表示する
node tools/prepare-verification-batch.mjs --difficulty beginner --count 10

# 5. 内容が一致した問題だけを確認済みにする
node tools/mark-verified.mjs <判定を書いたJSONファイル>
```

判定を書くJSONの形:

```json
[
  { "id": "cancer-beginner-001", "section": "4. 効能又は効果・18.1 作用機序" }
]
```

`section` には「添付文書のどこを見て確認したか」を書きます。URLと製品名は
`.pmda-cache/` から自動で埋まります。

## 確認の基準

**添付文書に書かれていることだけを根拠にする。** 自分の知識で補わない。

たとえば「シスプラチンの分類は?」→「白金製剤」は、添付文書の薬効分類名が
「抗悪性腫瘍剤」としか書いていなくても、化学名が `Diamminedichloroplatinum`、
分子式が `Cl2H6N2Pt` なので確認できる。一方「ドキソルビシンの分類は?」→
「アントラサイクリン系」は、添付文書のどこにも「アントラサイクリン」と
書かれていないため確認できない(下記参照)。

## 出典として認める資料

| 種類 | 可否 |
|---|---|
| PMDAの添付文書・インタビューフォーム | ○ |
| 学会・公的機関が公開する診療ガイドライン | ○ |
| **個人のブログ・まとめサイト** | **×** |

ガイドラインを出典にする場合も、公開元が学会・公的機関であることを確認し、
該当箇所のURLと確認日を記録する。

### `cancer-beginner-028` エリスロポエチン製剤とがん患者の貧血【削除済み】

問題:「エポエチンアルファなどエリスロポエチン製剤ががん患者に用いられる目的は」
旧データの正解:「化学療法に伴う貧血の改善」

エポエチンアルファ(バイオ後続品)の添付文書を確認したところ:

- **効能又は効果は「透析施行中の腎性貧血」「未熟児貧血」のみ**。化学療法に伴う貧血は
  効能に含まれていない。
- 5.2「腎性貧血であることを確認し、**他の貧血症…には投与しないこと**」と明記。
- さらに 15.1.5 に「**がん化学療法又は放射線療法による貧血患者に赤血球造血刺激因子製剤を
  投与することにより生存期間の短縮が認められたとの報告がある**」、15.1.7 に血栓塞栓症の
  発現頻度上昇の記載がある。

つまり日本の添付文書上、この用法は承認されていないだけでなく、**害を示唆する注意が
書かれている**。実習生向けの学習教材としてこの問題を出すのは適切ではない。

**対応: 2026-08-26 に削除した。** 同じ論点を扱いたい場合は「日本の添付文書では
がん化学療法に伴う貧血に対する承認はない」ことを問う問題として作り直す。

根拠: エポエチンアルファBS注750シリンジ 添付文書 4.効能又は効果 / 5.2 / 15.1.5 / 15.1.7

**成分名が似ている製剤は取り違えが起きやすい**ので、確認時は製品名を必ず見ること。

## 全体像として分かっていること

- 取り込んだ1,554問(1件削除後)のうち、出典が**添付文書・インタビューフォーム由来は898問**。
  残り**586問はガイドライン由来**で、PMDAの添付文書検索では確認できない。
  ガイドライン由来の問題をどう扱うかは別途決める必要がある。
- 出典にURLが入っていたのは1,009種類中わずか1件。確認作業のたびにURLを
  記録し直している。
- 症例(ケース)問題は2問しかない。設計書が求める「症例問題を混ぜる」
  構成にするには、別途作成が必要。
