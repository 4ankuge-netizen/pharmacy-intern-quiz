# 薬学実習生向けクイズアプリ 設計書

作成日: 2026-08-25

## 1. 目的・背景

薬学実習生(薬剤師を目指す実習生)向けに、実習先や同期に配布して使ってもらうクイズアプリを作る。8大疾患の薬物治療の知識に加えて、実習生・薬剤師として知っておくべき社会常識・倫理観も問う。品質の目標は「App Storeにあっても遜色ないレベル」。将来的には実際にApp Store/Google Playでの公開も視野に入れる。

## 2. 対象ユーザーと配布方法

- 対象:実習先の病院・薬局のスタッフや同期の実習生。数十人規模を想定。
- 端末:iPhone・Androidが混在。
- 配布方法:URL(リンク)を送るだけで使える形にする。アプリストアの審査待ちは発生しない。

## 3. 技術方針

- **Webアプリ(PWA: Progressive Web App)** として作る。ブラウザで開いて、ホーム画面に追加すればアイコンから起動でき、見た目・操作感を通常のアプリに近づける。
- 開発はWindowsパソコンのみで完結させる(Mac不要)。
- サーバー・アカウント登録は不要。ログイン機能は作らない。
- 学習記録(正解数・間違えた問題・ブックマークなど)は、利用者本人のスマホ内(ブラウザのローカルストレージ)にのみ保存する。
  - 制約として、ブラウザのデータを消去したり機種変更したりすると記録は失われる。今回はこれを許容する(長期保存やアカウント同期は今回のスコープ外、将来の拡張候補として保留)。
- 将来的に **Capacitor** という仕組みを使い、同じコードを土台にiPhone/Android向けの実機アプリに変換し、App Store/Google Playへの申請を目指せるようにする(作り直し不要)。
- **コンテンツ自動更新の仕組み**を用意する。Webアプリ(PWA)は何もしないと古いバージョンがスマホ内に残り続ける癖があるため、問題の追加・修正をしたときに、利用者が次にアプリを開いた際、自動的に最新版に切り替わるようにする。

## 4. コンテンツ構成

出題内容は次の **10カテゴリー** に分類する。各カテゴリーは **初級10問・中級10問・上級10問の合計30問** を初期の目標とし、10カテゴリー合計で**初期300問**を目指す。問題ストックはリリース後も継続的に増やしていく。

1. がん
2. 高血圧症
3. 糖尿病
4. 心疾患
5. 脳血管障害
6. 精神神経疾患
7. 免疫・アレルギー疾患
8. 感染症
9. 計算問題(用法用量・相互作用など。暗算で解ける範囲にとどめ、電卓が必要な複雑な計算は含めない)
10. 社会常識・倫理観(実習生・薬剤師としての守秘義務、マナー、報連相の姿勢など。具体的な小テーマは今後詰める)

上記1〜8の疾患カテゴリーの問題には、以下の内容を組み込む:

- 添付文書に基づく薬効・薬理・禁忌・併用禁忌・併用注意
- 副作用の初期症状の見分け方
- 妊婦・小児・高齢者など特殊な患者への注意点

(注記:1〜8の「代表的8疾患」の分類は、日本病院薬剤師会(JSHP)が公開する資料 `https://www.jshp.or.jp/content/2017/0622-2-3.pdf` の内容を実際に確認して採用したもの。)

## 5. 出題形式

一問一答形式のクイズを中心に、時々症例(ケース)問題を混ぜる構成とする。

### 5-1. 出題のランダム性(2026-08-26 追記)

問題プールは今後も継続的に増やしていく前提のため、出題は次の3段階すべてでランダムにする。

1. **どの問題を出すか**:カテゴリーの問題プール全体から、ランダムに **1回10問** を選ぶ。プールが何問に増えても、1回の出題は10問で区切る。
2. **出題する順番**:選ばれた10問の順番をランダムにする。
3. **選択肢の並び順**:**表示するたびに**選択肢を並び替える。同じ問題に再び出会っても並びは変わる。

選択肢の並び替えを「表示のたび」に行うのは、位置を覚えて中身を読まずに答えるのを防ぐため。データ側に固定の並びを持たせるのではなく、画面に出す瞬間に並び替える。

## 6. アプリの機能

- **弱点復習モード**:間違えた問題だけを繰り返し出題する
- **正答率グラフ**:カテゴリー・分野別に自分の得意不得意が見える
- **一次資料へのリンク**:解説文から、根拠にしたPMDAの添付文書・インタビューフォーム・ガイドラインの該当ページへのリンクを貼る
- **ブックマーク登録**:気になった問題に印をつけて後で見返せる
- **連続学習日数(ストリーク)表示**:毎日続けるとカウントアップされる、継続のモチベーション仕掛け

模試(タイマー付き)モードは今回は見送る。

## 7. 問題コンテンツの作成フロー

### 7-1. 守るべき原則(変更不可)

**8疾患の問題は、PMDAにある添付文書・インタビューフォーム、および診療ガイドラインから情報を取ってきて作成する。** これは本プロジェクトの前提であり、量を増やすことを理由に緩めない。

#### 出典として認める資料(2026-08-26 決定)

**3次情報(評価・整理された情報)を出典として認める。**

医薬品情報の分類でいう3次情報 — 添付文書、インタビューフォーム、診療ガイドライン、
教科書、総説 — が対象。個々の研究論文(1次情報)を直接の出典にはしない。

| 種類 | 可否 | 例 |
|---|---|---|
| PMDAの添付文書・インタビューフォーム | ○ | `info.pmda.go.jp/go/pack/...` |
| 学会・公的機関が公開する診療ガイドライン | ○ | 日本高血圧学会、日本糖尿病学会、日本感染症学会、厚生労働省、日本病院薬剤師会 等 |
| 教科書・成書 | ○ | 書名・版・該当ページを記録する |
| **個人のブログ・まとめサイト** | **×** | 3次情報として編集・査読を経ていないため採用しない |

いずれの場合も**どこを見て確認したか**を残す。Web上の資料はURLと確認日、
書籍は書名・版・ページと確認日を記録する。

**添付文書だけでは確認できない問題がある。** 特に次の2つは、性質上ガイドラインや
教科書を出典にする必要がある。

- **2剤の比較**(例:「第2世代抗ヒスタミン薬は第1世代より眠気が少ない」)
  … 片方の添付文書には比較が書かれない
- **服薬指導・患者への声かけ**(例:「飲み忘れたとき2回分まとめて飲まない」)
  … 添付文書は医療者向けの製品情報であり、こうした指導内容は載らない

1. Claude Codeが、PMDAサイト上の対象医薬品の**最新版**の添付文書・インタビューフォーム、および関連するガイドラインを確認する。
2. それらの一次資料をもとに、問題文・正解・解説を作成する。
3. 各問題には出典情報(資料名・URL・確認日)を必ず記録し、後から元資料と照合できるようにする。
4. 実際に実習先や同期に配布する前に、**利用者本人が全問をテストプレイし、内容の正確性を確認・修正する**。この最終レビューを経てから配布する。

医療系の内容はわずかな誤りが学習に影響しうるため、Claude Codeが一般知識のみで断定的に内容を生成することはせず、必ず一次資料を確認しながら作成し、人間による最終チェックを経る運用とする。

### 7-2. 確認済みフラグと出題対象(2026-08-26 追記)

各問題は `verified`(true / false)を必ず持つ。

- `verified: true` … 上記7-1の手順でPMDAの一次資料を実際に確認し、`source.url` と `source.confirmedDate` を記録したもの。
- `verified: false` … 未確認のもの。

**アプリは `verified: true` の問題だけを出題する。** 未確認の問題はデータとして保持するが画面には出さない。これにより、確認が済んでいない内容が学習者に事実として提示されることを構造的に防ぐ。

### 7-3. 旧プロジェクトからの取り込み(2026-08-26)

以前の別リポジトリ `pharmacy-core8-quiz` で作成済みだった8疾患1,555問を、本アプリの形式に変換して取り込んだ(`tools/import-legacy-questions.mjs`)。

重要な前提として、**これら1,555問は7-1の手順で作られたものではない。** 旧データのファイル冒頭に「一般的な医薬品情報・診療ガイドラインをもとに作成した学習用サンプル」と明記されており、出典欄も資料名のみでURL・確認日を持たない。

したがって取り込み時に全問 `verified: false` とした。これらは**下書きとして再利用する素材**であり、7-1の手順で一次資料と照合できたものから順に `verified: true` に切り替えて出題対象に加えていく。

取り込み時に行った補正:

- 旧データは**全1,555問とも正解が選択肢の1番目**に固定されていた(旧アプリが表示時に並び替える作りだったため)。取り込み時に並び替え、正解の位置を4か所に分散させた。この偏りはテストで継続的に監視する。
- カテゴリー名を本アプリのものに対応付けた(`heart`→`heart-disease`、`allergy`→`immune-allergy`)。
- 旧データに計算問題・社会常識・倫理観のカテゴリーは存在しないため、この2つは引き続き未作成。
- 症例(ケース)問題は旧データ中に2問のみ。5節の「症例問題を混ぜる」方針を満たすには別途作成が必要。

## 8. 今回のスコープ外(見送り事項)

- サーバー側のランキング・成績共有機能
- 模試(タイマー付き)モード
- アカウント登録・複数端末間の同期機能

いずれも将来的に必要になれば追加を検討できる位置づけとし、現時点の設計を妨げない。

## 9. 今後決めること

- アプリ名

## 10. デザインの方向性(2026-08-26 決定)

日本の調剤薬局・処方箋の世界観を土台にする。

**配色**

| 用途 | 色 | 由来 |
|---|---|---|
| 見出し・ヘッダー | `#1B2A4A` 深藍(紺) | 教科書や公式文書のきちんとした印象 |
| 強調・正解・ボタン | `#1B7C64` 調剤薬局の緑 | 日本の薬局の看板に使われる緑 |
| 背景 | `#FAF8F3` 処方箋紙の白 | 真っ白ではない、紙の温かみ |
| 判子・不正解 | `#B5483D` 朱色 | 判子の朱肉 |
| 補助文字 | `#6E685D` グレー | |

緑とグレーは、小さな文字でも読みやすさの基準(コントラスト比4.5:1)を満たす濃さに調整済み。

**文字**:見出し・アプリ名は明朝体(Shippori Mincho)、本文はゴシック体(Zen Kaku Gothic New)。長い症例文を画面で読む都合上、問題文はゴシック体とする。

**シグネチャー(このアプリならではの目印)**:正解したときだけ「正」の**判子**が押される演出。不正解のときは判子を押さず✕印のみとし、判子に特別感を持たせる。

**各画面の表現**:カテゴリー一覧と選択肢は罫線で区切ったリスト、正答率はカルテ・帳簿風の罫線表、ブックマークは控え・レシート風の点線区切り。
