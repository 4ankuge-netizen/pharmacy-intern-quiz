# このアプリをもう一度作るためのプロンプト

このファイルは、`薬学実習クイズ` を最初から作り直すための指示書です。
新しい会話の最初のメッセージとして、下の「プロンプト本体」をまるごと貼り付けてください。

## 先に知っておいてほしいこと

**このプロンプトで出てくるのは「同じ仕組み」であって、「同じ1,912問」ではありません。**

問題とその出典の確認は、1問ずつ添付文書やガイドラインを読んで突き合わせる作業で、
何十回もの往復を重ねて積み上げたものです。プロンプト1枚では再現できません。
できるのは「同じ作り方・同じ確認のルールで、問題を積み上げていける状態」までです。

問題データそのものを引き継ぎたい場合は、`data/questions.json` をコピーしてください。

# プロンプト本体（ここから下をコピーして貼り付ける）

薬学部の実習生（5〜6年生）向けのクイズアプリを、一緒に作ってください。
私が指導薬剤師で、実習に来る学生に配ります。

## 私について

- プログラミングは完全な初心者です。専門用語（配列、state、イベント、DOM など）は
  できるだけ使わず、身近なものに例えて説明してください。ただし説明は要点だけ簡潔に。
  聞いていない詳細まで先回りしないでください。
- やり取りはすべて日本語でお願いします。
- コードには、私が後で読み返して分かるよう、各処理に簡単な説明コメントを多めに残してください。
  （「コメントは書かない」という一般的な原則より、こちらを優先してください）

## 進め方

- **1つの作業が終わったら、そこで必ず止まってください。** 次に何をするか提案するのは
  構いませんが、私が指示するまで勝手に次へ進まないでください。
- **分からないこと・確認していないことを、事実のように答えないでください。**
  推測なら「推測ですが」と明示してください。存在が不確かなファイル・関数・API・情報は、
  断定する前に実際に調べてください（コードを読む、検索する、取得して中身を見る）。
  それでも確認できなければ「分からない」と正直に言ってください。
- 作った機能は、**実際に動かして確かめてから**「できました」と言ってください。
  テストを書いて通す、ブラウザで操作する、生成したファイルの中身を読む、のいずれかです。

## 何を作るか

スマートフォンのブラウザで開く、一問一答形式の学習アプリです。

### 技術的な制約（ここは崩さないでください）

- **素の HTML / CSS / JavaScript のみ。** ビルド作業なし、npm の依存パッケージなし。
  ES モジュール（`<script type="module">`）で組んでください。
- 開発用の簡易サーバーだけ自作して `npm start` で動かします（`dev-server.js`）。
- テストは Node 標準の `node --test` を使います（`npm test`）。
- **PWA にしてください。** マニフェストとサービスワーカーを用意し、一度開けば
  電波がなくても使えるようにします。
- 最終的に **GitHub Pages** で公開します。URL を知っていれば誰でも開けます。

理由は、私が保守できる範囲に収めたいからです。ツールが増えるほど、
何かが壊れたときに私の手に負えなくなります。

## 問題データ

`data/questions.json` に、1問を1つのまとまりとして並べます。形はこうしてください。

```json
{
  "id": "cancer-beginner-001",
  "category": "cancer",
  "difficulty": "beginner",
  "type": "single",
  "question": "アプレピタントの主な使用目的として正しいのはどれか。",
  "choices": ["…", "…", "…", "…"],
  "correctIndex": 0,
  "explanation": "…",
  "source": {
    "name": "アプレピタントカプセル125mg 添付文書 4. 効能又は効果",
    "url": "https://www.info.pmda.go.jp/go/pack/…",
    "confirmedDate": "2026-08-26"
  },
  "verified": true
}
```

- `id` は `カテゴリー-難易度-3桁の番号` で固定します。あとで成績を短い文字列に
  置き換えるときに、この形を前提にします。
- `difficulty` は `beginner` / `intermediate` / `advanced` の3段階。
- `type` は既定が `single`（4択）。ほかに `case`（症例つき）と `query`（後述の疑義照会）。
- **`verified` が `true` の問題だけをアプリに出します。** 確認が済んでいない問題は
  データには置いても出題しません。

### カテゴリー

疾患8分野に、実習で必要な3つを足した12分野です。

| id | 名前 |
|---|---|
| `cancer` | がん |
| `hypertension` | 高血圧症 |
| `diabetes` | 糖尿病 |
| `heart-disease` | 心疾患 |
| `cerebrovascular` | 脳血管障害 |
| `psychiatric` | 精神神経疾患 |
| `immune-allergy` | 免疫・アレルギー疾患 |
| `infection` | 感染症 |
| `calculation` | 計算問題 |
| `ethics` | 社会常識・倫理観 |
| `national-exam` | 国家試験（必須問題のみ） |
| `prescription-query` | 疑義照会 |

`data/categories.json` に id と名前だけを並べ、この並び順を正とします。

## 出典と事実確認のルール（このアプリの背骨です）

**ここが最も大事です。** 実習生は、ここに書いてあることを正しいと思って覚えます。
間違いを覚えさせるくらいなら、問題を減らしてください。

1. **すべての問題に、確認できる出典を1つ付けてください。** 出典は次のいずれかです。
   - PMDA の添付文書（`info.pmda.go.jp/go/pack/…`）
   - PMDA のインタビューフォーム
   - 学会の診療ガイドライン
   - 厚生労働省の通知・指針・国家試験問題
   - e-Gov 法令検索の法令・省令
2. **三次情報（教科書・総説・ガイドライン）を根拠にします。** 個人のブログ、
   まとめサイト、出典のない一覧表は使わないでください。
3. **「たぶんこうだったはず」で書かないでください。** 用量・禁忌・適応は、
   必ず添付文書の該当項を実際に取得して読み、その項番号まで `source.name` に書いてください。
   （例:「2.8 禁忌（妊娠後期の女性）」）
4. **有料・会員限定の資料は使わないでください。** 私も実習生も読み返せません。
   途中でそういう出典が混ざっていたら、無料で読めるものに差し替え、
   何をどう変えたかを `docs/question-revisions.md` に記録してください。
5. **時間で変わる内容には注意してください。** ガイドラインの版、食事摂取基準の年版、
   ドーピング禁止表など、毎年変わるものは解説の中でその旨に触れてください。
6. 資料を取得する道具は `tools/` に作り、取得先ごとに分けてください
   （添付文書用・インタビューフォーム用・ガイドラインPDF用・法令用）。
   取得したファイルは `.gitignore` に入れて、Git では管理しません（再取得できるため）。

### 問題を追加するときの流れ

`tools/add-question.mjs` を作ってください。問題を書いた JSON ファイルを渡すと、

- そのカテゴリー・難易度で空いている次の番号を `id` に付ける
- `correctAnswer`（正解の文言）から `correctIndex` を計算する
- 書き込む前にデータ全体の形を点検する
- 追加した内容と出典を `docs/question-revisions.md` に追記する

を行います。**あとから「なぜこの問題が入ったのか」をたどれるようにするため**です。

## アプリの機能

### 出題の流れ

1. ホームでカテゴリーを選ぶ（各カテゴリーに何問あるか添える）
2. 難易度を選ぶ（初級・中級・上級。それぞれ問題数とこれまでの正答率を添える）
3. **1回10問。** 問題プールが何問に増えても、1回分は10問で区切ります。
   出題順も選択肢の並びも毎回変えてください。
4. 答えると、その場で正解・不正解、解説、出典が出ます
5. 解き終わると結果画面。正答率を円グラフで出し、その回の10問を1問ずつ開いて
   解説を読み返せるようにしてください

### そのほか

- **弱点復習モード** — 直近の回答が不正解だった問題だけを出します
- **ブックマーク** — 気になった問題に印を付けて後で見返せます
- **正答率** — カテゴリー別の正答率を棒グラフで
- **連続学習日数** — 何日続いているか
- **利用者の切り替え** — 1台の端末を複数の実習生が使います。成績・ブックマーク・
  連続日数は利用者ごとに分けて保存し、混ざらないようにしてください
- **成績の書き出し** — 今の利用者の成績を文字にまとめてコピーできる

保存先はブラウザの localStorage です。保存するときの名前の後ろに利用者の番号を付けて
分けてください（例: `pharmacyQuiz.history:p_abc123`）。
利用者を分ける仕組みを後から足す場合は、番号が付いていない古いデータを
1人目に引き継いで、それまでの記録が消えないようにしてください。

### 疑義照会カテゴリーの特別な出題形式

このカテゴリーだけ、2段階で答えさせてください。

1. 症例と処方を読み、**「疑義照会は不要」／「疑義照会が必要」** の2択に答える
2. 「必要」が正解でそう答えた場合のみ、**理由を5択**から選ぶ

「不要」を選んだ時点で採点が終わります（理由を聞く必要がないため）。

問題の中身は次の形式で統一してください。

```
【症例】
患者情報: 年齢 性別
既往歴: …
検査値: …
特記事項: …

【処方内容】
〈診療科・継続処方か新規処方か〉
Rp1) 薬剤名 規格  数量
     用法  日数

【問題】
この処方について、疑義照会が必要か判断してください。
```

解説は次の見出しで揃えてください。

- 照会が必要な場合: 【問題点】【考えられるリスク】【疑義照会例】【根拠】（必要なら【補足】）
- 照会が不要な場合: 【問題点】【考えられるリスク】【薬剤師の対応】【根拠】

**とても大事な点が2つあります。**

- **疑義照会が「必要」な症例を70%、「不要」な症例を30%にしてください。**
  不要な症例を混ぜるのは、「何でも照会する」のではなく、本当に必要なケースを
  見分ける訓練にするためです。
- **薬局で処方される薬に絞ってください。** 点滴など病院の中でしか出ない薬は省きます。

扱う話題は、腎機能による減量漏れ、相互作用、重複投与、用法の誤り、高齢者への
不適切処方、妊婦・授乳婦・小児の禁忌、投与日数の上限、検査値異常、ハイリスク薬などです。
同じ薬で「必要な例」と「不要な例」を対にすると、線引きが覚えやすくなります
（例: コデインを8歳に＝禁忌／15歳に＝問題なし）。

## 成績を指導者に集める仕組み

実習生の成績を、私の手元でまとめて見られるようにしてください。
ただし **実習生が見られたくない場合に断れること** が絶対条件です。

### 実習生が選ぶ3段階

| 選択 | 指導者に見えるもの |
|---|---|
| **共有しない（初期値）** | 何も表示されない |
| 正答率だけ共有する | 分野ごとの正答率・回答数・連続学習日数 |
| すべて共有する | 上に加えて、間違えた問題の一覧 |

- **初期値は必ず「共有しない」にしてください。**
- 「正答率だけ」を選んだときは、**間違えた問題を送信前に端末側で落としてください。**
  指導者の画面で隠すのでは不十分です。届いていなければ見ようがない、という状態にします。
- 利用者を作った直後に1回だけ尋ね、あとは利用者画面でいつでも変えられるようにしてください。
- 「共有しない」に戻すときは、**それまでに送った分も消すかどうかを選べる**ようにしてください。
  一度送ったら取り消せない、という状態にしないでください。

### 送り方

- ボタンを押させないでください。**10問解き終わるたびに、裏で自動的に送ります。**
- 電波がなければ送らず、次にアプリを開いたときに送り直してください。
- 前回と中身が同じときは通信しないでください。

### 送る中身の作り方

問題IDをそのまま並べると長すぎるので、短い文字列に置き換えてください。

- カテゴリーを1文字（categories.json の並び順）、難易度を1桁、あとは番号
- 連続した番号は範囲にまとめる
- URLに入れても化けない記号だけを区切りに使う（`~ * ! . -` は化けない。`, : |` は化ける）

```
すべて共有   PQZ1~2026-09-11~12~a1 3-6.12!8.9
             （がん・初級の 3,4,5,6,12番が正解、8,9番が不正解）
正答率だけ   PQZ1S~2026-09-11~12~a1:9/12*b2:3/5
             （数だけ。どの問題を間違えたかは含まれない）
```

全1,900問すべてに答えた状態でも4千文字ほどに収まります。

**日付や連続学習日数が壊れていたら、送る前に直してください。** `undefined` が
混ざった文字列を送ると、実習生の画面には「送信済み」と出るのに指導者には何も
届かない、という双方が気づけない壊れ方をします。

### 受け取り側

Google スプレッドシートに Google Apps Script を付けて、ウェブアプリとして公開します。

- `doPost` … 成績を受け取り、**1人1行**で上書きします（行が増え続けないように）。
  `action: 'delete'` を受け取ったら、その人の行を消します。
  同時に送られても行が壊れないよう `LockService` で順番待ちさせてください。
- `doGet` … **合言葉が合っているときだけ**、全員分を返します。

**合言葉は Apps Script 側にだけ置き、アプリのソースコードには入れないでください。**
ソースコードは公開されるため、URL は誰でも見られます。そのままだと誰でも
全員の成績を読めてしまいます。書き込みは誰でもできますが（見覚えのない名前が
混ざっていないか私が確認します）、読み出しは合言葉で守る、という形にしてください。

ブラウザから送るときは `Content-Type: text/plain` にしてください。
`application/json` にすると送信前の確認通信が発生し、Apps Script はそれに返事をしないため失敗します。

### 指導者用の画面

- アプリの中に作りますが、**実習生の画面には入口を置かないでください。**
  URL の末尾に `#teacher` を付けて開いたときだけ表示します。
  （鍵をかけているわけではありませんが、この画面は入力されたものを表示するだけなので、
  開かれても誰かの成績が漏れることはありません）
- 合言葉を入れて読み込むと、次の3つを表示します。
  1. 全員の一覧（名前・回答数・正答率・連続学習日数・最終更新）
  2. 分野ごとの正答率を、実習生を横に並べて比較する表
  3. 一人ずつ、間違えた問題の一覧（分野・難易度・問題文・正解）
- **「表示されるのは共有する設定にしている実習生だけです」と画面に明記してください。**
  これがないと、載っていない人を「勉強していない」と誤解します。
- 「正答率だけ」の人の欄は空にせず、**なぜ間違えた問題が出ないのかを書いてください。**
  空欄だと「全問正解」と読み違えます。
- 通信がうまくいかないときのために、表計算から貼り付けて読む逃げ道も残してください。

## 見た目

「ありがちなテンプレート」に見えないようにしてください。方向性はこうです。

- 配色は、教科書や公式文書を思わせる**濃い藍色**をヘッダーに、
  日本の調剤薬局の看板でよく使われる**緑**を「進む」ボタンに、
  背景は真っ白ではなく**少し温かみのある紙の色**にしてください。
  正解したときは**朱色の判子**が押される演出を入れてください。
- 見出しだけ**明朝体**にすると、参考書のような佇まいになります。
- カテゴリー12個それぞれに色を割り当て、ホーム・正答率・ブックマークの3画面で
  同じ色を使ってください。色でカテゴリーを覚えられるようにするためです。
- 難易度にも色を割り当ててください（やさしい順に緑→青→紫）。
- 色や大きさは CSS の変数にまとめ、あちこちに直接書かないでください。
- **ダークモードに対応してください。** 変数の中身を差し替えるだけで済む作りにします。
- **パソコンで開いたときに左右が大きく余らないようにしてください。**
  ただし本文の幅をそのまま広げると1行が長くなりすぎます（日本語は1行30〜40字が読みやすい）。
  タブを画面左の縦一列に移し、カードが並ぶ画面は列を増やし、
  文章を読む画面は幅を抑えたまま中央に置く、というように内容ごとに変えてください。

## 配布物

実習生に配る A4 1枚の案内を作ってください（`docs/qr/`）。

- 公開URLの QR コード（誤り訂正レベルは最高にして、汚れや欠けに強くしてください）
- 使い方の手順
- できることの一覧
- **成績の共有設定の説明**（3段階の表、変えかた、取り消せること、何が送られるか）
- PDF で書き出せるようにしてください

QR コードは画像ファイルを参照せず、図形として HTML に直接埋め込んでください。
1つのファイルで印刷でき、拡大しても荒れません。
**作ったら、PDF から実際に読み取れることを確かめてください**（印刷解像度を変えて試す）。

## 先に知っておいてほしい落とし穴

実際に作ったときに引っかかった所です。同じ所で止まらないよう、先に伝えておきます。

**厚生労働省の PDF が文字化けする**
国家試験の問題PDFなどは、`pdftotext` で読むと「ø ೔໨ᶃ」のような文字化けになります。
Python の PyMuPDF（`pip install pymupdf`）を使うと正しく読めます。

**サービスワーカーが古いファイルを保存してしまう**
`cache.addAll()` は、ブラウザが少し前にダウンロードして持っているファイルを
そのまま使うことがあります。GitHub Pages は最大10分ほどファイルを持ち回すため、
「新しい版として保存したのに中身は古い」という、次の更新まで直らない状態になります。
`new Request(url, { cache: 'reload' })` を渡して、必ず取りに行かせてください。

**選択肢の A・B・C の番号が続いてしまう**
CSS のカウンターで選択肢に記号を振る場合、`counter-reset` は同じ階層の
後ろの要素には効きません。リセットを持つ要素で選択肢を囲んでください。

**正解の位置が偏る**
問題を書いていくと、正解が1番目に集まります。正解の位置を均等に散らす道具を
作ってください。**選択肢の数ごとに分けて数えてください**（4択と5択を混ぜて数えると
計算が壊れます）。

**Google Apps Script への送信が失敗する**
上に書いた `Content-Type: text/plain` の件です。

**先生用画面を後から隠す**
入口のボタンを消すだけでなく、戻るときに `#teacher` を URL から消してください。
付けっぱなしだと、次に開いたときにいきなり指導者用の画面が出ます。
